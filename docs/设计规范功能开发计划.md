# 「设计规范」功能开发计划

> 版本：v1.0 ｜ 状态：待评审 ｜ 范围：设计规范（Design Tokens）空间 + 走查合规校验 + 多格式导出

## 1. 背景与目标

在工作空间中新增「设计规范」能力：按端分类管理 Figma 设计规范 Token，与走查项目绑定，走查时自动用 Token 做合规校验，并支持一键导出 JSON / CSS / Tailwind 三种格式供前端直接消费。

### 1.1 已确认的关键决策（三轮提问结论）

| 决策点 | 结论 |
| --- | --- |
| 入口结构 | 侧边栏独立入口「设计规范」，与项目列表/报告中心平级；页面内按端分类一级菜单切换 |
| 绑定关系 | 规范库挂工作空间层；走查项目**按端绑定多套**规范，走查时按页面端类型自动取对应套 |
| 端分类 | 预置 4 类（PC 端 / 移动端 / 可视化大屏 / Electron 桌面端），**支持自定义增删** |
| .fig 文件 | 仅上传存档作附件，**Token 提取以 Figma 链接 API 解析为准** |
| 提取策略 | Figma Variables/Styles 优先，无变量时启发式扫描图层兜底 |
| 一期 Token 范围 | 颜色、间距、字号、行高、圆角、阴影、边框 共 7 类；组件基础属性放二期 |
| 一键同步 | 覆盖当前 Token + 保留历史版本，可回看/回滚 |
| 合规校验 | 程序比对（硬指标容差）+ AI prompt 注入 双轨 |
| 不合规呈现 | 新问题来源「规范合规」进入问题清单，复用采纳/忽略流转 |
| 导出 | JSON（W3C 风格）+ CSS `:root` 变量 + Tailwind v3 `theme.extend`；保留 Figma 原名、`/` 转层级命名，导出前可预览 |
| 绑定入口 | 新建走查项目表单可选 + 项目详情随时改绑 |

## 3. 数据模型设计（Dexie v6）

```
specCategories   端分类（一级菜单）
  id            string  主键
  name          string  分类名（预置：PC 端/移动端/可视化大屏/Electron 桌面端）
  platformKey   'h5'|'pc'|'dashboard'|'electron'   映射的页面端类型（走查取套依据）
  builtin       0|1     预置标记（预置可改名/不可删；自定义可删）
  sortNo        number  排序
  createdAt     number

designSpecs      规范套（一个端分类下多套）
  id            string  主键
  categoryId    string  索引 → 所属端分类
  name          string  规范名
  figmaUrl      string  Figma 规范链接
  figmaFileKey  string  解析出的 file key
  figFileName   string  Figma 文件名（同步回填）
  figArchivePath string  .fig 上传存档路径（仅存档不解析）
  note          string  备注
  lastSyncedAt  number  最近同步时间
  createdAt / updatedAt

specVersions     同步历史
  id            string  主键
  specId        string  索引
  no            number  递增版本号（V1..Vn）
  syncedAt      number
  sourceFileKey string
  tokenCount    number
  summary       string  变更摘要（新增/删除/修改 计数）

specTokens       Token 行
  id            string  主键
  specId        string  索引
  versionId     string  索引 → 所属版本
  kind          'color'|'spacing'|'fontSize'|'lineHeight'|'radius'|'shadow'|'border'
  name          string  Figma 原名（如 color/primary）
  path          string  层级路径（/ 分组，导出命名依据）
  value         string  JSON 序列化值（色值 / 数值+单位 / 多层阴影结构）
  source        'variable'|'style'|'heuristic'   提取来源
  description   string  Figma 变量描述

projectSpecBindings  项目绑定（一项目可绑多套，每端一套）
  id            string  主键
  projectId     string  复合索引 [projectId+specId]
  specId        string
  createdAt
```

**走查取套路径**：`page.platform` → 匹配 `specCategories.platformKey` → 该项目绑定中属于该分类的规范 → 取其最新 `specVersion` 的 Tokens。

**版本策略**：同步时新写一条 `specVersions` + 全量重写该版本 `specTokens`；「当前生效」= 最新版本。回滚 = 将历史版本 Token 复制为新版本（保留审计链，不物理删除）。

## 4. 页面与交互流程

### 4.1 规范库页 `SpecsPage`（路由 `/specs`）
- 侧边栏新增「设计规范」入口（图标 + 文案，走 i18n `layout` ns 扩展）
- 顶部：端分类 Tab 横条（末尾「管理分类」按钮 → 弹窗内增删改、排序；预置 4 类可改名不可删）
- 规范卡片列表（按分类过滤）：名称、Token 数、最近同步时间、绑定项目数、同步/导出快捷操作
- 新建规范弹窗：名称、Figma 规范链接（必填其一规则：链接必填）、.fig 文件上传（存档）、备注

### 4.2 规范详情（弹窗或抽屉）
- Token 表：按 7 类分组 Tab、关键词搜索、来源徽标（variable / style / heuristic）、heuristic 项可隐藏
- 「一键同步」：调主进程解析 → 覆盖入库 → toast 摘要（新增/删除/修改 N 项）
- 「历史版本」抽屉：版本列表、变更摘要、回滚按钮（二次确认）
- 「导出」：见 §7

### 4.3 项目绑定
- 新建走查项目表单（ProjectModal）：按端分类分组的规范选择器（可不选，默认不绑定）
- 项目详情页：横幅操作区「绑定规范」入口 + 已绑定规范展示，点击改绑

## 5. Figma 解析链路（主进程）

### 5.1 通道
- IPC：`spec:sync`（specId）→ 主进程拉取并解析 → 返回 Token 集合 → 渲染层写 Dexie
- 复用 `main/figma.ts` 的 PAT 读取、代理 fetch、错误封装

### 5.2 解析优先级
1. **Variables API**：`GET /v1/files/:key/variables/local` 与 `/variables/published`
   - 映射：`COLOR`→color、`FLOAT` 按变量名归类 spacing/fontSize/lineHeight/radius、`STRING` 兜底
   - 403/无权限 → 降级并 toast 提示（需组织/企业版变量权限）
2. **Styles**：文件节点 `styles` 字段（颜色/文本/效果样式）
3. **启发式兜底**（对未建变量的设计稿）：
   - 遍历 DOCUMENT 节点（限深 14、限量，参考 diff.ts 现有遍历）
   - 统计：fills/strokes 颜色频次、cornerRadius、itemSpacing / padding、fontSize、lineHeight、effects、strokeWeight
   - 聚类：颜色量化去重取 TopN、间距/字号做 4/8 网格归一后按频次聚合，`source='heuristic'`

### 5.3 合并策略
Variables / Styles 结果优先占位同名 Token；启发式仅补充缺失类别；同类超量（>50）时按频次截断并在摘要中说明。

## 6. 走查合规校验（双轨）

### 6.1 程序轨（新增 `src/renderer/src/spec/specCheck.ts`）
- 输入：`devCollectScript` 采集的样式树 + 项目绑定规范的最新 Tokens
- 规则：
  - color：与 Token 集合做容差比对（RGB 距离阈值，复用 `shared/color.ts`；色板外 → 不合规）
  - spacing：间距值不在 Token 集合 ±容差内 → 不合规
  - fontSize / lineHeight / radius：±容差精确比对
  - shadow / border：结构比对（层数、色值、模糊/扩展、权重）
- 输出：不合规项列表（节点、属性、实测值、最接近 Token、偏差量）

### 6.2 AI 轨
- 自动走查 prompt 注入 Token 摘要（按类分组；每类 Top 30，超限截断并注明）
- 指引模型输出「规范合规」类问题候选（语义性：搭配、层级、一致性）

### 6.3 结果流转
- `IssueSource` 扩展 `'spec'`：程序轨直接生成候选（`isAISuggested: true` 待采纳）；AI 轨随现有候选回流
- IssueList / SourceBadge / IssueEditorModal / ExportReport 全链路支持 `spec` 来源（含 i18n）

## 7. 导出器（`src/shared/tokenExport.ts` 纯函数）

| 格式 | 产物 | 命名规则 |
| --- | --- | --- |
| JSON | W3C 风格分组对象（按 `/` 分组嵌套，含 `$value`/`$type`） | 原名保留，`/` 转层级 |
| CSS | `:root { --color-primary: ...; }` | path → `--` + kebab 拼接 |
| Tailwind v3 | `theme.extend = { colors: { primary: ... }, spacing: {...}, ... }` | path → 嵌套对象（camelPath） |

- 导出弹窗：格式多选、实时预览（只读代码块）、复制到剪贴板 / 另存为文件（主进程 dialog）

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Variables API 需要 PAT 具备相应计划权限（组织/企业版） | 403 时自动降级启发式 + 明确 toast 指引；设置页连通性测试提前暴露 |
| 启发式扫描噪声多 | Token 标记来源；详情页支持隐藏 heuristic 项；频次/网格归一阈值可调 |
| 自定义端分类与页面端类型映射歧义 | 分类创建时强制选择映射的 `platformKey`；走查取套只认 platformKey |
| Token 过多导致 AI prompt 超限 | 分组截断（每类 Top 30）+ 摘要化；后续可做按页白名单 |
| 回滚语义歧义 | 采用「复制为新版本」的追加式回滚，保留完整审计链 |
| Dexie 升级 | 纯新增表，`version(6)` 无数据迁移；回归现有 v5 数据读写 |

## 10. 明确不在本期范围

- .fig 文件本地解析提取 Token（仅存档）
- 组件基础属性（按钮/输入框等尺寸与状态样式）提取
- SCSS / Tailwind v4 CSS-first 导出格式
- 规范跨工作空间共享 / 云端同步
